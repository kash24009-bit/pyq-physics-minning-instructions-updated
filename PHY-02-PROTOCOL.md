- `pyqkit pack vault --batch N` writes **one JSON file**: `PHY-VAULT-B<nn>-<YYYYMMDD-HHMM>-<rows>r.json`. It contains every vault file as text, with a sha256 per file and STATE.
- She keeps the newest one in project knowledge. Text files are stored raw on disk there.
- **Restore:** `pyqkit restore vault [--db DIR]` scans:
  - `/mnt/project/PHY-VAULT*.json`
  - `/mnt/user-data/uploads/**/PHY-VAULT*.json` (and legacy `.zip`)
  - a database dump directory

  It verifies every checksum and ignores zero-row copies when a non-empty one exists. It then picks the newest by (batch, created_utc, rows) and prints each candidate with its verdict. File names are never trusted (Mistake B12).

### 3.3 The auto-vault — automatic backup between sessions
- **Batch 0:**
  1. `pyqkit vault-page > /mnt/user-data/outputs/phy042-vault.html`
  2. Artifact `publish`: title "PHY-042 VAULT", favicon 🗄️, capabilities `{db: {}, assets: {}}`. She approves once.
  3. **Round-trip test:** `db-export` → `write_db` → `read_db` → `db-import` into scratch → checksums compared. PASS → `vault_url` goes into STATE and CONVENTIONS. FAIL → noted; the vault-file route alone continues.
- **Every checkpoint:**
  1. `pyqkit db-export vault /mnt/user-data/outputs/dbx` writes documents (≤180 kB each) and `writes-NNN.json` plans (≤50 entries, manifest last).
  2. For each plan: Artifact `write_db` with `db_op: "batch"` and `writes` = the plan's entries (each carries `file_path`, so no content passes through the chat).
- **Restore:** Artifact `list` → `read_db` `db_op: "list"` on collections `meta` and `vault`, `out_dir: /mnt/user-data/outputs/dbin` (page with `query.limit` and `query.cursor`) → `pyqkit restore vault --db /mnt/user-data/outputs/dbin`.

## P§5 · INTAKE AND IDENTITY

### 5.1 How the platform stores files
- **Chat attachments:** originals in `/mnt/user-data/uploads` (ZIPs are unpacked by `inventory`).
- **Project knowledge:**
  - PDFs are bundles at `/mnt/project/<name>.pdf`: a ZIP holding `manifest.json` (pages, dimensions, `has_visual_content`), one JPEG per page (~924 px wide, ~110 dpi) and one `.txt` per page. PDF metadata is lost.
  - `.md`, `.csv` and `.json` files are stored as-is.

### 5.2 What `inventory` decides
- **kind:** QP, MS, SQP, SQP-MS, APQ, SYLLABUS, NCERT, EXEMPLAR, COMPILED, OTHER, UNKNOWN. Decided from the page-1–2 text, never the file name.
- **paper code:** `55/1/1`, `55/C/1`, `55/B`, with any separator (`/`, `_`, `-`). A scheme printed for several sets fills `sets_covered` (e.g. `1,2,3`).
- **year evidence**, strongest first:
  1. printed "Examination, 2025";
  2. printed session, where the latest session mentioned is the paper's own;
  3. **scheme footer code `YY-SS-SSN`** (2026 schemes, e.g. `26-03-42N`);
  4. the file or ZIP name prefix;
  5. PDF creation date (originals only; weak).

  All evidence is recorded. If a name contradicts the page, the page wins.
- **exam:** MAIN, COMPT, SQP, APQ, T1, T2, UNK.
- **language:** en / hi / bi (bilingual papers alternate pages; English pages are listed).
- **status:** NEW, IN-PROGRESS, DONE, QUARANTINE, DUP-FILE, UNAVAILABLE.

### 5.3 Permanent files are recognised, not mined
- The PHY-0x files, the vault file and the syllabus: logged with `kind = OTHER` or `SYLLABUS`.
- SQP 2026-27 and its scheme are mined once, at Batch 0.

### 5.4 Scheme-year check (W-1)
Every MS/SQP-MS in `/mnt/project` must match the year being mined. Any mismatch is reported in the boot report, and that scheme is not used as PRINTED for this year.

## P§6 · READING A PHYSICS PAGE

### 6.1 Image-first, and the dual-read
- Every question and every scheme line is read from the page image.
- **Dual-read** (bundles and any page with a text layer): take the structure from the image (fraction bars, exponents, vectors, which symbol is where) and cross-check every digit against the page text (`pages --text N`).
  - Example: the image shows 3 × 10^8 with a small raised 8; the text shows "3 × 108"; together they give `3e8`.
  - A conflict between the two gets a note and a 300-dpi crop from the original if available; otherwise UNREADABLE `LOWRES`.
- **Known text-layer damage** (VERIFIED in SQP 2026-27): 10⁸ → "108"; hν → "h"; ¹⁶₈O → "168O"; 30° → "300"; B₁/B₂ → "B and B".

### 6.2 Render settings
- **Originals:** 200 dpi grayscale with `--crop`; 300 dpi `--region` crops for anything small.
- **Bundles:** native JPEG, cropped, never downscaled.
- **Bilingual papers:** English pages only; `--pair` puts two pages in one image.
- **Hindi pages** are the backup when English is missing or damaged (`read_from = hi-translation`).

### 6.3 Normalisation — plain ASCII, one convention
| Write it as | Examples |
|---|---|
| Plain maths | `E = (1/(4*pi*eps0)) * q/r^2` |
| Powers of ten | `3e8 m/s`, `1.6e-19 C` |
| Greek letters and constants | `mu0`, `eps0`, `lambda`, `nu`, `phi0`, `theta`, `omega` |
| Vectors and unit vectors | `vec(B)`, `i^ j^ k^` |
| Angles | `30 deg` |
| Subscripts | `B_1`, `R_eq` |
| Minus signs | `-` |

- The unit is part of the value (`12 V`).
- Directions and printed signs are copied exactly.
- Misprints stay with `(sic)`.

### 6.4 Figures are data
Every printed figure → FIGURES row:
- **circuit:** netlist, e.g. `R1=2 ohm A-B; E=6 V r=1 ohm C-A; ammeter A-B series`;
- **ray diagram:** elements, focal lengths, positions, sizes;
- **graph:** axes and units, curve shapes, marked points, intercepts, slopes;
- **field/apparatus:** components and labels.

A figure she must draw → a FIGURES row with `printed_or_demanded = demanded` and `labels_required`.

### 6.5 Unreadable is logged, never guessed
UNREADABLE row with `problem` ∈ LOWRES / MISSING / DAMAGED / CUT, what was lost, and any recovery source. The optional list gets one plain sentence.

### 7.1 INSTANCES — field rules
- **instance_id:** `<paper_id>-Q<nn><side>[-<part>…]`.
  - Parts use printed labels joined by `-`: `2025-5511-Q31A-a-ii`.
  - Two separate demands in one unlabeled stem → `-d1`, `-d2`.
  - VI alternative → `-VI`.
  - No dots anywhere.
- **side:** `A`/`B` for internal-choice alternatives as printed (old papers print only "OR": the first is A).
- **marks_part:** only when printed for that row; otherwise blank. Never split marks equally.
- **q_marks_printed:** the question's printed total, on every row of that question.
- **choice_pair_id:** `OR-<paper_id>-Q<nn>` on both sides.
- **case_id:** `CS-<paper_id>-Q<nn>`.
- **vi_alt:** `y` for visually-impaired alternatives. Excluded from mark sums.
- **chapter:** `01`–`14`; `15` for Communication Systems (deleted chapter); `X11` for Class 11 content.
- **topic_id:** from SYLLABUS only.
- **q_type:**

  | Code | Meaning |
  |---|---|
  | `MCQ` | multiple choice |
  | `AR` | assertion–reason |
  | `DEF` | define / state a law / unit / dimension |
  | `CON` | explain / why / give reason |
  | `PRD` | how does X change / what happens if |
  | `NUM` | numerical |
  | `DRV` | derive / obtain / show that / prove |
  | `DGM` | draw or label a diagram |
  | `GRF` | plot, sketch or interpret a graph |
  | `CMP` | compare / distinguish |
  | `DEV` | principle, construction or working of a device |
  | `EXP` | experiment-based |

- **command_verb:** the printed instruction word.
- **options:** mandatory for MCQ: `A) … | B) … | C) … | D) …`. For AR, the option set is stored once per paper in `extra` as `ARSET=…`.
- **givens / unknown:** for NUM rows, e.g. `d=0.25 mm; D=1.0 m; lambda=500 nm` and `beta`.
- **stem:** from the image, normalised (P§6.3).
- **read_from:** `image`, `bundle-image`, `photo`, `hi-translation`.
- **rel / rel_to:** P§7.4.
- **syllabus_status:** `IN`, `DELETED`, `VERIFY-DEL`, `X11`, `UNK`.
- **extra:** `key=value; …` for anything the schema lacks. Reviewed at every schema review.

### 7.2 Other field rules
- **FIGURES / FORMULAE:** `from_image` must be `y`.
- **FORMULAE.role:** `given`, `asked`, `scheme`, `result`. `source` = QP / MS.
- **STEP-AWARDS.step_kind:** `formula`, `substitution`, `result`, `unit`, `diagram`, `label`, `reason`, `definition`, `key`, `other`.
- **STEP-AWARDS.provenance:** `PRINTED`, `TRANSFERRED:<award_id or paper_id>`, `INFERRED`. One provenance kind per instance.
- **CASES.context:** a two-sentence summary of the passage's setting and physics. Never the passage copied at length.

### 7.3 Case studies
Each sub-part is its own INSTANCES row with its own q_type. `attempt_rule` records "any 4 of 5" and similar.

### 7.4 Relations — computed, then confirmed on images
| rel | Meaning | Counts in frequency as |
|---|---|---|
| `origin` | First extraction | one event |
| `shuffle` | Same year and series, other set; identical wording AND numbers | part of the origin's event |
| `variant` | Same year and series; same skeleton, changed numbers or wording | part of the origin's event; new number-design sample |
| `repeat` | Near-verbatim in another series or year | its own event; feeds the recycling rate |

`pyqkit similar` proposes; Claude confirms each on the images (numbers and units). Report line format: `Set 55/1/2: 29 shuffle, 3 variant, 1 new`.

## P§9 · SCHEME PASS (STEP-AWARDS)

The scheme is read from the rotating file on disk, question by question.

- **One row per scoring line** as printed: text, marks (½ allowed), kind, mandatory, alternatives.
- **MCQ/AR:** one `key` row, e.g. `(B)`.
- **Numeric results** found only in the scheme → FORMULAE `role = result`, `source = MS`.
- **Examiner instructions** (the general-instructions page) → CONVENTIONS + register R14 (e.g. 2026: both options marked and the higher counts; error penalised once; competency credit).
- **Several sets in one scheme:** map by the scheme's printed cross-reference, else by `similar`. Shuffle rows inherit the origin's steps (no duplicate rows). Variant rows get PRINTED rows only where the scheme prints that set's version; otherwise structure-only `TRANSFERRED` rows, never another set's numbers.
- **No scheme for a paper:** copy the scoring structure of the same archetype from a year with a printed scheme (`TRANSFERRED:<award_id>`); otherwise `INFERRED`, clearly labelled.
- **Old one-page schemes** (final answers only): the answer is a PRINTED `result` step; method steps are INFERRED.

## P§10 · JUDGED LAYER — ARCHETYPES, CLASSIFICATION, REGISTERS

### 10.1 Schemas
```
CLASSIFY   instance_id code family cog_level competency difficulty ncert_ref confidence batch rule_version
REGISTRY   code family chapter topic_id q_type name asks_you_to skeleton traps status alias_of
           issued_batch first_instance note
SYLLABUS   topic_id mark_group group_marks unit chapter chapter_name topic status limitation source
```
- **cog_level:** `REM`, `UND`, `APP`, `ANL` (analyse/evaluate/create). The syllabus target is 27/22/21 marks.
- **competency:** `y` if the item applies a concept to an unfamiliar or real situation, interprets data or a graph, or is case- or assertion-based.
- **difficulty:** `E` / `M` / `H`.
- **ncert_ref:** filled only in the end-phase source trace (e.g. `NCERT-12-P1-Ex3.7`, `EXEMPLAR-3.21`).
- **confidence:** `H` / `M` / `L`.
- **REGISTRY.status:** `DRAFT` (seed, no instance yet), `VERIFIED`, `ALIAS`, `SPLIT`.

### 10.2 The granularity test (one sentence, applied to every assignment)
> Two events share an archetype **iff** a student who has mastered the scoring skeleton of one would score full marks on the other with no new idea — only different numbers, wording or context.

### 10.3 Classification procedure (every row, every year, before year-close)
1. Run `pyqkit candidates vault --instance <id> --k 5`, which searches the same chapter first (name tokens + stems of existing instances).
2. Apply the granularity test to the top candidates.
3. If a candidate passes:
   - VERIFIED → assign it;
   - DRAFT → assign it, set status VERIFIED, and fill `first_instance`.
4. If none passes → issue a new code (next free serial in that chapter) with:
   - name (a plain verb phrase of 12 words or fewer);
   - asks_you_to (one sentence of 30 words or fewer, starting "Asks you to …");
   - q_type, topic_id and family;
   - **skeleton** (the fixed lines that score, drawn from the printed scheme when one exists);
   - **traps** (what loses marks, with year).
5. MCQ/AR archetypes are named by the concept tested plus "(MCQ)" or "(A-R)".
6. **One code per row.** A multi-concept stem is split into rows first.
7. **Split:** issue new codes, re-classify the affected rows, set the old code to `SPLIT` with a note. **Merge:** set the newer code to `ALIAS` pointing to the older.
8. **Families** (`FAM-cc-nn`) group archetypes by concept, e.g. "Gauss's law applications". A family is added when the first archetype of a new concept appears.

### 10.4 Eligibility (for statistics)
A year is eligible for an archetype when a main paper of that year exists and the archetype's chapter is in that year's syllabus. Term years count only for their term's chapters.

### 10.5 The eighteen registers (derive writes CSV + MD, grouped by chapter)
| # | Register | Built from |
|---|---|---|
| R01 | Derivations | DRV rows + scoring lines |
| R02 | Numerical skeletons | NUM rows: givens, unknown, formula chain, unit trap, number design (value ranges) |
| R03 | Reasons | CON rows + accepted points and how many points the marks demand |
| R04 | What-happens-if | PRD rows |
| R05 | Definitions, laws, units | DEF rows |
| R06 | Diagrams | DGM or `wants_figure` rows + labels required |
| R07 | Graphs | GRF or `wants_graph` rows |
| R08 | Devices and instruments | DEV rows |
| R09 | MCQs | MCQ rows + options + distractor notes |
| R10 | Assertion–Reason | AR rows + the option set per year |
| R11 | Case studies | CASES + sub-part types |
| R12 | OR-pairs | pairs, codes, chapters, types per side |

## P§11 · THE YEAR PIPELINE AND THE DEFINITION OF DONE

**PROGRESS.md work lines for a year**, created at S1:
```
- [ ] Y2025 S1 intake
- [ ] Y2025 S3 2025-5511 ledger  (one line per distinct paper)
- [ ] Y2025 S4 siblings 55/1   (one line per series)
- [ ] Y2025 S5 schemes 55/1    (one line per scheme file)
- [ ] Y2025 S6 classify chapters 01–14
- [ ] Y2025 S7 derive + workbook
- [ ] Y2025 S8 validate + year-close + vault
```

**Stage detail:**
- **S1 Intake** — `inventory` + the scheme-year check (P§5.4). Papers are grouped into series (`55/1/x`). One origin per series is chosen (the most legible set). Siblings are queued for S4.
- **S2 Blueprint** — per paper, from its own instructions page.
- **S3 Ledger** — per paper, via the CI§6 loop.
- **S4 Siblings** — `similar --year Y` → confirm → rows. Set-specific questions are extracted fully.
- **S5 Schemes** — P§9.
- **S6 Classify** — P§10.3. Before classifying, predict which existing archetypes this year should contain (from ARCHETYPE-STATS). After classifying, record the misses in `notes/Y<year>.md`: predicted but absent; present but new.
- **S7 Derive** — `derive` then `export-xlsx <year>`. Write `notes/Y<year>.md`: observations (recycled questions, SQP resemblance, difficulty notes), each backed by instance ids.
- **S8 Close** — `validate`, `year-close <year>`, `pack`, db-export + `write_db`, `present_files`: vault file, year report, workbook.

**Definition of Done:** the ten checks of CI§5, implemented by `year-close`. On PASS, the year is added to `STATE.years_closed`, and the report ends with the three swap steps for her.

## P§15 · THE PREDICTION ENGINE AND MOCK GENERATOR

### 15.1 Honest scope
The engine predicts the **menu**: which archetypes, in which sections, at which marks, with which scoring lines. It does not predict wording. The only accuracy claims allowed are backtest numbers.

### 15.2 Archetype scorecard (`derive` → `ARCHETYPE-STATS.csv`, PRESENCE scope, main exam)
| Measure | Meaning |
|---|---|
| `n_years`, `eligible_years`, `p_year` | Presence rate |
| `recency` | Presence weighted by a 3-year half-life |
| `due` | (target year − last seen) / median gap, capped at 2 |
| `sqp_target` | Appears in the target year's SQP |
| `spread` | Share of that year's series papers carrying it |
| `marks_seen`, `sections_seen` | Where and at what marks it appears |

**Default score (uncalibrated):** `0.5·recency + 0.2·due/2 + 0.2·sqp + 0.1·spread`. After backtests, the weights that maximised marks-weighted hit rate replace it, and the label becomes "backtested on <years>".

### 15.3 `plan-mock` — the slot plan (deterministic for a given seed)
1. **Skeleton:** the 2027 blueprint (from the SQP 2026-27 BLUEPRINTS row; default P33 with choice at 20, 21, 27, 31–33).
2. **Allowed types per section:** learned from STRUCTURE papers; defaults:
   - A = MCQ (Q1–12), AR (Q13–16);
   - B = CON/NUM/DEF/PRD/CMP/DGM/GRF;
   - C = NUM/DRV/CON/DGM/GRF/DEV/PRD/CMP;
   - D = case (MCQ-style sub-parts);
   - E = DRV/NUM/DEV/GRF combinations.
3. **Mark-group quotas** from SYLLABUS: G1 16, G2 17, G3 18, G4 12, G5 7. Side A of each OR counts.
4. **Filling order:** E, D, C, B, then A. Candidates are archetypes whose type fits and whose group still has quota. One archetype per paper; a family at most twice.
5. **Mode ranking:**

   | Mode | Ranks by |
   |---|---|
   | `likely` | Score |
   | `seed` | Weighted random by score |
   | `stress` | NUM/DRV first, low `p_year` first |
   | `wildcard` | Boosts archetypes seen in one year or fewer |
   | `coverage` | Penalises codes used by earlier mocks |
   | `chapter` | Restricts to one chapter |

6. **OR alternatives:** same mark group, different family.
7. **Blocked:** DRAFT, SPLIT, ALIAS codes; topics DELETED or VERIFY-DEL; a limitation conflict (no derivation for "no derivation" topics, no numericals for "qualitative only").
8. **Scarcity rule:** bigger slots favour mark groups whose remaining marks exceed their unused archetypes, and 1-mark slots fill the scarcest group first, so quotas can close exactly.
9. **Quality gate** (checked by the kit):
   - every group quota is met exactly;
   - no fatal flag (`quota overflow`, `no candidate`, `no OR alternative`).

   Soft flags (`type relaxed`, `family cap relaxed`) are allowed and shown. The kit retries seeds (`--tries`, default 20) until the gate passes. A chapter drill (`--mode chapter`) is as long as that chapter's distinct archetypes allow (minimum 8 slots).
10. **Output:** `PLAN-<mode>-<seed>-<time>.csv` + `.md`: slots, codes, names, groups, reasons, quota check, thinking-level mix vs 27/22/21, gate verdict.

### 15.4 Writing the mock (Claude, from the plan)
- **Each slot is instantiated as one of:**
  - (a) a **real PYQ**, labelled with its year (practice mode only);
  - (b) a **variant**: same skeleton, new numbers chosen for clean arithmetic (no calculator);
  - (c) a **fresh** item: new context, same scoring skeleton. Case passages are original writing.
- **Numbers:** every numerical is solved in Python, with units carried and a dimension check. MCQs have exactly one correct option; distractors follow R09 patterns.
- **The paper:** CBSE look (general instructions, 15-minute reading note, constants list, sections, internal choices, VI alternative for figure-dependent MCQs). Figures are drawn with matplotlib/schemdraw, or described in words for VI.
- **The marking scheme:** CBSE value-point style with ½ splits, from printed STEP-AWARDS templates where they exist (provenance shown).
- **The WHY file:** per question, code, evidence (years), score components, why it was chosen.
- **Files:** `PHY-MOCK-<nnn>-<mode>.pdf`, `PHY-MOCK-<nnn>-MS.pdf`, `PHY-MOCK-<nnn>-WHY.md`, made with the pdf skill (reportlab).
- **Logged** in MOCKS.csv (codes, sha256, UTC time) and **frozen**.

### 15.5 Quality gates — all checked before anything is shown
- Blueprint, quotas and choice layout exact.
- No blocked item.
- Every numeric verified in Python.
- Thinking-level mix within ±4 marks of 27/22/21.
- No archetype twice.
- The PDF renders.

## P§16 · BACKTEST AND THE GAME
**Backtest:** for each held-out Y in {2024, 2025, 2026} (once those years are closed):
1. Train on data before Y, plus the SQP released for Y's session (it existed before the exam).
2. `derive --until Y-1`.
3. Predict a `likely` plan and a `coverage 5` set.
4. `backtest --year Y`.

**Metrics:** event hit rate, marks-weighted hit rate, per-section hit rate, near-verbatim hits, mark-group error.

**Baselines, always shown:** SQP only; last year only; random (mean of 100). Trust is claimed only where the engine beats all three.

**The Game:** after the February 2027 exam, the real paper is mined like any paper. `Score.` rates every mock frozen before the exam date. **Student picks:** before the exam she may log her own top 10, scored the same way. One gloat line allowed.

## P§17 · CHAPTER BRIEFS — built on how memory and skill actually form
One page, on `Brief me on chapter N.` Every section applies a named learning principle:

```
CHAPTER BRIEF — Ch 03 Current Electricity (Unit II · mark group G1 = 16) · evidence: <years> · stamp B<nn>
Worth            ~X marks/paper (STRUCTURE papers) · last 3 years: a, b, c
Always there     archetypes present in ≥80% of eligible years
Top 5            code · name · asks_you_to · marks seen · last seen · score
Scoring lines    the printed steps for the top 5 (formula ½ · substitution ½ · result + unit ½ …)
                 [worked example → faded example: first fully worked, then with steps blanked]
Derivations      step skeletons in 3–5 chunks each                      [chunking]
Numericals       formula chain · unit trap · typical numbers            [deliberate practice targets]
Reasons          accepted points, how many points the marks demand     [elaboration]
Draw these       diagrams and graphs with mandatory labels             [dual coding]
Traps            the five costliest, with years                        [error-focused practice]
Skip             zero-event and deleted topics
Recall set       10 prompt → answer cards (formulas, definitions, reasons)
                 [retrieval practice; review at 1-3-7-14-30 days = spacing]
Practice         6 real PYQs mixing different archetypes, in learning order,
                 + one generated variant each                          [interleaving]
Presentation     OSM rules: number exactly, one part per block, box results with units,
                 label every diagram, both OR options only if time remains (2026 rule)
```

The recall set can be sent to the study project as flashcards (the quiz card tool). A unit brief has the same shape across its chapters.
